# Manager window and settings

Code: `src-tauri/src/manager.rs`, `src/windows/manager/manager.html` / `manager.js` / `manager.css`, `src/lib/i18n.js`. Find sections with `memo-code-map`.

## Window

Label `manager` (`MANAGER`), page `manager.html`. Behaves like a note — frameless, same titlebar (pin, +, …, ✕) plus a quick "new group" button (`#newGroupBtn` → `new_group`) before the +; "bring all memories to the front" (`bring_notes_to_front`) is in its titlebar menu (… / right click, `MemoChrome.titleMenu`), and "new group" is also in the app part of every titlebar menu; drag with snapping, resize, middle-click close via `chrome.js`; position/size/pinned/colour persisted in `FileData.manager` (`ManagerState`). Fixed title ("Gerenciador"/`manager_title`), no double-click action, no editor. Colour control: a manager icon drawn in its colour (`#mgrColorBtn`, same swatch popover; `ManagerState.color`, default iris, `set_color`). `set_pinned`, `set_color`, `close_window` and `track_geometry` treat a window with no `Kind` as the manager; ✕ / middle click → `close_window` (in Memo Web on mobile, the manager is the primary view and cannot be closed: ✕ is hidden and Fechar/Close is excluded from the title menu). Opened by `open_manager` at startup / relaunch, from the tray item and a tray left click; notes have no button for it. Notes snap to it and `+` from it opens a note beside it.

Every change to the note list emits `notes-changed` (`notify`); the manager reloads `list_notes` (all notes, `html` stripped) on it, debounced. Also `groups-changed`, `store-replaced` (reloads the page).

## Tabs

Four equal-width `.tab` buttons (no counts): **Memórias**, **Grupos**, **Configurações**, **Ajuda**. When a tab can't fit its label (small window, zoom, language), `fitTabs` sets `.mgr-head.compact` and one `#viewSelect` replaces them.

- **Memórias** and **Grupos** have search and sort, plus a segmented `#scopeSwitch` Atuais | Lixeira (`scopes[view]`, `inTrash()`). The trash scope shows `#trashBar` (info + empty button: `empty_trash` / `empty_group_trash` / `empty_board_trash`, asks for a second click) and trashed cards (`noteTrashCard` / `groupTrashCard`: restore, delete for good, days left). There is no separate Lixeira tab.
- Both lists are rendered from cards (`.list` is a CSS grid of ~200 px columns in cards mode by default, or `.as-list` rows). A card (`card()` in manager.js: `.card-head` with the colour dot or folder and the title, `.card-preview` renders text components with limited height, `.card-foot` = date or days left + `.card-actions`, always visible). Help shows one with `.demo-card`. Settings → Aparência → Visualização (`#layoutSwitch`, also the tray's "Visualização do Gerenciador" submenu) switches both tabs between list and cards: `ManagerState.layout` (`"cards"` default, `"list"`; `LAYOUTS`, `Store::manager_layout`) via `set_manager_layout` → `layout-changed`; `applyLayout` puts `.as-list` on `#list`, which restyles the same cards as rows (CSS only; the preview joins lines with " · " instead of newlines).
- Note cards (`noteCard`): click → `open_note`; a closed note is a dimmed `.is-closed` card; the foot shows the edit date and, only when it has them, its group and each board it is on (`boardsOf`) as `.pill`s (`pill()`: folder or board icon in its colour + name; display only — groups and boards are changed from the windows, not the manager; their names count in the search); the trash button (`move_to_trash`) is an X (`.card-x`, the titlebars' trash icon) that `card()` moves to the card's upper right corner (the end of the row in the list layout), on memory, group and board cards alike. Trash: `restore_note`, `delete_forever`.
- Group cards (`groupCard`): folder colour, out/put-away state, count; click → `focus_group`; buttons → `toggle_group_id` / `trash_group_id`; trash: `restore_group`, `delete_group_forever`.
- Middle click on a memory or group (list or cards, `auxclick` on `#list`) = its trash button (`move_to_trash` / `trash_group_id`) or delete button in trash (`delete_forever` / `delete_group_forever`); ignored on the `<select>`.
- **Configurações** and **Ajuda** are split in sections (`.sec`, each starting with its `.settings-title`; Settings ones carry `data-sec`, Help ones their index) that open and close with a click on the title (`makeToggle` wraps the title's first span in a `.sec-toggle` button with a chevron; the "i" stays beside it). All sections start closed by default (`openSecs`, by `data-sec`; `.is-open`). In those tabs the search row (`#searchBox`) hides the scope and sort; the search (own text per tab, `queries` / `swapQuery`; Memórias and Grupos share theirs) shows every `.setting` or Help topic that matches from all sections, with their sections open (`renderSections`, `.is-off` on the rest; a matching section title shows the whole section); Help topics match on topic + text (`dt[data-find]`), not demos. The tray's update items open the App section (`showSection('application')`). A new settings group is a new `.sec` with a `data-sec` and its title text in a span.
- **Configurações** (no list): appearance (theme, layout, zoom, language), new-note defaults, new-group defaults, AI control (switch, Connect buttons for the MCP clients found, client picker that copies the setup), storage/backup (`memo-storage`), app (window magnet on/off — `memo-windows`, start with the system, quit → `quit_app`, second click). `fitSettings` sizes the label column to the widest visible label (`--label-w`; labels never wrap) and stacks every label above its control (`.settings.stacked`) only once some control no longer fits.
- **Ajuda**: the how-to guide (below).

## Settings

- **Sync** (Configurações → Sincronização, `[data-cloud]` rows, shown only when the build has a Google OAuth client): `get_cloud_account` → `(available, email, status)`, `sync_cloud` ("Sync now"), `connect_cloud` (browser sign-in, see `memo-storage`; errors are codes `denied`/`timeout`/`network`/`keyring`/`cancelled`/`busy` mapped to `cloudErr*` strings), `cancel_cloud_connect`, `disconnect_cloud`; Rust emits `cloud-changed`. State and rendering: the "cloud" section of manager.js (`renderCloud`, also called on language change). Help has a "Sincronização / Sync" item under Configurações.
- **Theme:** `FileData.theme` = `system` | `light` | `dark` (empty = system), segmented switch → `change_theme` → `set_theme`: saves, updates every window's native background (`apply_background`: `PAPER` or `CARBON`; "system" uses `window.theme()`, re-applied on `WindowEvent::ThemeChanged`) and emits `theme-changed`. Pages read `get_theme` and set `<html data-theme>` (no attribute = follow `prefers-color-scheme`).
- **Language:** `FileData.language` = `system` | `pt-BR` | `en`; `Store::effective_language()` → `"pt"` or `"en"` (system: `sys-locale`, Portuguese for any `pt*` locale). Pages call `get_language` → `(setting, effective)` and `MemoI18n.set(effective)`. `#languageSelect` → `change_language` → `set_language`: emits `language-changed`, rebuilds the tray (`refresh_tray`, main thread), retitles the manager. Rust strings: `tray_labels`, `manager_title`, `storage_text`, `welcome::for_lang`. Note content and defaults are never translated.
- **i18n in pages:** static text uses `data-i18n="key"` and `data-i18n-attr="attr=key,…"`; JS uses `t('key', vars)` (parameters are never named `t`). Every new string goes in both `pt` and `en`; reuse existing keys (tooltips with their shortcut, placeholders, confirmations) instead of near-duplicates.
- **Zoom:** `FileData.zoom` (`ZOOM_MIN`..`ZOOM_MAX` by `ZOOM_STEP`, 1.0 = 100%), from Aparência (− / % / + / reset) or Mod + / Mod − / Mod 0 / Mod + wheel in any window (`MemoZoom` in chrome.js, also in the embedded editor) → `change_zoom(step)` (0 = reset) → `set_zoom` on every app window + `zoom-changed`; new windows get it when built. Group bars are `TITLEBAR_H × zoom` tall; `resize_to`'s minimum height scales too.
- **New-note defaults:** colour (`get_default_color` / `set_default_color`, `FileData.default_color`, `None` = no colour, `DEFAULT_NOTE_COLOR`; `"random"` = a random label per note, resolved by `Store::new_note_color`), title (`set_default_title`), text via the embedded editor (`memo-editor`, `set_default_content`). Plain-text `[ ] ` lines become checklist items via `fromPlain`. `trash()` deletes outright a note still equal to the defaults (`is_pristine`).
- **New-group defaults** ("Padrão dos grupos"): `FileData.default_group_color` (`None` = a random label per group, offered as the shuffle swatch `data-color="random"` / `RANDOM_COLOR`; `random_group_color` picks among the least used of `RANDOM_COLORS`; `is_pristine_group` then checks the group was never edited) / `default_group_title` (empty = unnamed) via `get_group_defaults`, `set_default_group_color`, `set_default_group_title`; applied by `Store::create_group`.
- **Start with the system:** `tauri-plugin-autostart` (name "Memo", argument `--autostart` = `AUTOSTART_ARG`; Windows Run registry value, macOS LaunchAgent, Linux `~/.config/autostart`). The Windows NSIS installer asks with a checkbox on its welcome page, checked by default (`src-tauri/windows/hooks.nsh` via `bundle.windows.nsis.installerHooks`; writes/removes `HKCU\…\Run\Memo`, removed on uninstall; its functions attach to the welcome page because Tauri includes the hooks before the pages). macOS and Linux have no installer step, so `init_autostart` turns it on at the first run of a release build (`Config.autostart_init` in `config.json`). Switch: `get_autostart` / `set_autostart`.
- **Version:** the App section shows the running version (`window.__TAURI__.app.getVersion()`, from `tauri.conf.json`); the tray shows the same as a disabled item above "Sair do Memo". Beside it, "Procurar atualizações" (`check_update`) or, once a newer version is found, "Atualizar e reiniciar" (`install_update`), with a status line below (checking, up to date, available, download %, errors) fed by `get_updates` and the `update-changed` event (`updater::Status`); the "Avisar de novas versões" switch (`set_auto_update`, `Config.updatesOff`) turns the automatic checks off. Details in `docs/updates.md`.
- **AI control (MCP):** `Config.ai_control` (off by default) via `get_ai_control` → `(on, exe)` / `set_ai_control`, also the tray check item; both go through `toggle_ai_control`, which starts/stops the endpoint (`mcp.rs`) and emits `ai-control-changed`. While on, `#aiClientsRow` lists the MCP clients installed here (`get_ai_clients` → `clients::list`: `connected`, `current` = launches this executable, `unreadable`) with Connect / Update / Disconnect (`connect_ai_client(id, on)` → `clients::connect`, which edits only the `memo` entry of the client's config file, keeps `<file>.before-memo`, writes atomically; refreshed on window focus). A new client goes in `clients()` with its file, marker folder and format. `#aiSetup` ("Other app") lets the user pick a client format (`AI_SETUPS` in manager.js: `mcpServers` JSON for Claude Desktop/Cursor/Windsurf/Gemini CLI…, VS Code's `servers` JSON, `claude mcp add` / `codex mcp add` commands, or the bare `exe --mcp` command) and copies it; the setup must stay client-neutral (any MCP client over stdio). Tools and protocol: `mcp.rs` and docs/development.md.

## Help guide (Ajuda)

Groups are data in `i18n.js` (`HELP`, `MemoI18n.help()`, pt/en), rendered by `renderHelp`. In each "how" text `{{…}}` marks a key or something to type, shown as `<kbd>` through `keys()` (Mod → Ctrl/⌘). Items are `[topic, how, demo?]`: `demo` is optional static HTML (`demoBox`) drawn like the real thing — editor markup (`b`/`i`/`u`, `.hl`, `.sz-2`/`.sz-5`, `.check`, `.bullet`, `code`, `pre.code[data-lang]` highlighted with Prism, which manager.html also loads), `<i data-icon="…">` for chrome icons (pin, pin-on, plus, close, folder, folder-plus, manager, raise, toggle, search, sort; paths in the help section of manager.js) and `.demo-*` mock-ups in manager.css. Add a demo whenever a feature can be shown. Prism token colours live in base.css. Keep the guide in sync when features or shortcuts change. The "open the welcome memory" button → `show_welcome`.
