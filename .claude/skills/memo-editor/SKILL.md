# Note editor (`app.js`)

`app.js` is a single IIFE (~1.6k lines); find sections with `memo-code-map`. Text saves are debounced 250 ms and flushed on blur / window blur / beforeunload; `save_text(text, html)` stores both. Pin toggling is optimistic and reverts on error.

## Note window chrome

Titlebar: pin far left, colour dot (`#colorBtn` → swatch popover `#colorMenu`), name, then new / close on the right (always visible). Drag, resize, middle-click close (`auxclick` → `closeNote`, same as ✕) and double-click rename (inline `#titleInput` → `set_title`, max 80 chars) come through `MemoChrome.attach` (`chrome.js`); resize handles and the bottom-right grip are `chrome.js` too. The name (or first line) is mirrored to the native window title (`setTitle`). Footer: `#footBtn` shows the group (see `memo-groups`). The native context menu is suppressed everywhere except the editor and the title input. Shortcuts: Mod+Shift+P pin, Mod+N new note (Mod = ⌘ on Mac, Ctrl elsewhere).

## Stored format

`#editor` is a `contenteditable` div; each line is a `<div>`. The note stores `html` (the editor's `innerHTML`, re-sanitised on load by `sanitize` to this whitelist) and `text` (plain text via `toPlain`). Rust only reads `text` (`is_blank`); a note with empty `html` is rebuilt from `text` (`fromPlain`). Paste is always plain text (images apart: see app.js "images"; they are data URLs in the editor, files on disk, see `memo-storage`).

- Bold/italic/underline: `<b>`/`<i>`/`<u>` (`styleWithCSS` off). Bold must render at weight ≥ 600 or `queryCommandState('bold')` (and Ctrl+B toggling off) breaks.
- Highlight: `<span style="background-color: rgb(255, 230, 0)">` from `execCommand('hiliteColor')` — only that exact sentinel counts (Chromium creates other background spans). WebKit (macOS/Linux) puts the style on the `<b>`/`<i>`/`<u>`/`<font>` itself when the selection is exactly that element, so `sanitize` keeps the sentinel on those too and the CSS rule matches any element; removal sets `transparent`. Mod+Shift+H or the marker button.
- Text size: `<font size="2|3|5">` from `execCommand('fontSize')` (`SIZES` in app.js; real px in the `.editor font[size]` CSS rules — keep both in sync). Mod+Shift+> / Mod+Shift+< (matched by `e.code` Period/Comma).
- Checklist item: `<div class="check">` (checked: `check done`, box drawn in CSS `::before`). Bullet: `<div class="bullet">`. Numbered: `<div class="number">`. All can carry `data-level` 1–4 (`LIST_TYPES`, `isListItem`).
- Inline code: `<code>`. Code block: `<pre class="code" data-lang>` holding only text and `<br>`.
- Table: `<table>` (class `head` when the first row is a header) > `<tbody>` > `<tr>` > `<td>`, straight in the editor like a line; cells hold inline content only (`sanitize` flattens anything else, `<th>` rows from outside become `head`).
- Plain text: items are `[ ] ` / `[x] ` (`[]` also accepted by `LIST_RE`/`plain`), bullets `- `, numbered `1. ` (any number is read back; written from `data-n`), each level two leading spaces (`listPrefix`, `LIST_RE`); inline code `` `x` ``, code blocks ```` ```lang … ``` ```` fences (`fromPlain` parses both); tables as `| a | b |` lines (`tableLines` / `cellText`; a header row is followed by `| --- | --- |`, `\|` is a pipe in a cell; `fromPlain` reads a run of such lines, `TABLE_ROW_RE` / `TABLE_SEP_RE` / `rowCells`, and so does `from_plain` in mcp.rs); U+200B is stripped.
- Presentation-only attributes (dropped by `sanitize`/`contentHtml`, recomputed): `syncNumbers` (on load and every change) gives each numbered item its `data-n` (counts within a run at the same level; deeper items don't break it, anything else does; CSS shows it with `attr(data-n)`). `syncCheckSizes` (on load and every change) gives an item whose text is all one `<font size>` a `data-size` so the line takes that size; mixed-size items get an inline `--check-mid` with the measured first-line centre.

## Lists

Typing `[]` at line start makes a checklist item; `- ` makes a bullet and `1. ` a numbered item (`expandBullet`); a space typed right after is dropped. Clicking the box toggles it without moving the caret. Enter continues the list (the browser clones the block; `done` is cleared). Tab / Shift+Tab change level (`setLevel`). Clicking left of the box/dot, or ArrowLeft at the item's start, puts the caret "before the marker" (`setBeforeMarker`, a drawn `#markerCaret`): Enter there pushes the item down, and a typed character or dead key goes on a new plain line above (`typeAbove`, shared with code blocks). Enter on an empty item or Backspace at its start outdents first, then leaves the list.

## Code

- Inline: typing `` `x` `` → `expandInlineCode`, or Mod+E / `</>` → `toggleCode`. Dead-key backticks (ABNT2, US-International) are covered too: the closing backtick may arrive with the next character (`insertText` "`,", kept after the code) or as a composition (`compositionend` handler). Inserted straight into the DOM with a trailing U+200B so the caret leaves the code (Chromium's `insertHTML` would copy inline styles). ArrowLeft (`boxArrowLeft`, also for highlights and bold/italic/underline — `<b>`/`<strong>`/`<i>`/`<em>`/`<u>`, `isTextStyle` — via `currentBox`/`isBox`) stops before the code's first letter, still inside (Chromium jumps out from the second letter), and from there puts the caret just before the code, in the text there or a new U+200B node (Chromium skips that spot, so at a line start there was no way to type before the code); list `atStart` checks ignore U+200B so the next ArrowLeft goes before the marker. ArrowRight mirrors it (`arrowRight`): from the end of a line followed by a list item or code block it goes before that one's marker, then into its text; before a box (`boxAfterCaret`) it stops inside before the first letter; at a box's end it goes after it (behind a U+200B so typing stays out).
- Block: ```` ```lang ```` + Enter → `openCodeBlock`. Inside: Enter = line break, Tab = two spaces, Enter on an empty last line leaves; ArrowLeft at its start goes "before the marker" (`setBeforeMarker(pre)`, as list items: caret drawn left of the block, Enter pushes the block down, a typed character or dead key goes on a new line above); list/inline conversions are disabled. `preText` reads it (Range.toString ignores `<br>`). `codeLang` normalises `data-lang` (aliases `js`/`py`/`sh` → `CODE_LANGS` values; unknown names kept as typed).
- Highlighting is presentation only: the pre's own text is `color: transparent`, and `renderCode` (on every content change, scroll, resize and language change) lays one item per block in `#codeLayer` (a sibling of the editor inside `.body`, never saved) with Prism's highlighted copy (`src/vendor/prism.js`: vendored core + 20 languages, `data-manual` — don't read it) mirroring the block's computed font/padding/wrapping. The block's top padding is a header row, so the `<select class="code-lang">` (top-left, `setCodeLang`; always shown as a quiet label, a button while hovered) and the copy button (`.code-copy`, top-right, only while hovered → `copyCode`: `preText` to the clipboard via a synchronous `copy` event so the editor keeps focus, `navigator.clipboard` fallback; a check for 1.5 s). Token CSS (`--code-*` in base.css, both themes) uses colours only — bold/italic would change glyph widths and misalign the copy.

## Tables

"tables" section of app.js. Created by `| a | b |` + Enter on a plain line (`tableRowOf` → `openTable`: that row plus an empty one), the table button (`toggleTable`: inside a table → back to `| a | b |` lines keeping formatting; with a selection its lines become rows, split on `| |` or tabs, a `| --- |` second line → header; caret only → `insertEmpty('table')`, an empty 3×2 table, `TABLE_COLS`/`TABLE_ROWS`). Keys in a cell (`onTableKeydown`): Tab / Shift+Tab next / previous cell (Tab in the last adds a row), Enter the cell below or the line after the table (cells never hold line breaks; paste joins lines), Backspace at a cell's start goes to the previous cell and in an empty row's first cell deletes the row, Delete at a cell's end does nothing, ArrowUp in the first row of a table that starts the note adds a line above. Outside (`tableEdgeKey`): Backspace at the start of the line after a table / Delete at the end of the line before one go into the table instead of merging. `expandCheckbox`/`expandBullet` are off in cells; inline code works. `syncTables` (in `applyContent`) keeps rows the same width, `<br>` in empty cells, no empty tables, a line after a trailing table. `caretInCell` puts the caret at a cell's end after a U+200B when a box ends it.

`#tableLayer` (over the editor, like `#codeLayer`, never saved) belongs to the table under the mouse (`tableNear`, `setHoveredTable`, watched on `.body`): "+" buttons centred on the left / right edges (a column on that side, `addColumn`) and bottom edge (`addRow`), each shown only while the pointer is near that edge; a tools pill on the bottom-right corner: header row on/off (`toggleHeader`), delete row / column (`deleteRow`, `deleteColumn`) of `targetCell` (the caret's cell in that table, else the last hovered), with `.table-mark` tinting what would go. Deleting the last row or column deletes the table (`deleteTable`). The Format menu adds the same commands plus add row/column and delete table while the caret is in a table (`tableMenuItems`). Not in the tray icon menu: it needs a note's caret.

## Undo

The editor keeps its own history ("undo" section): many edits change the DOM directly, which Chromium's undo stack never sees. `onContentChanged(typing)` records a snapshot (HTML + selection as child-index paths) after every change (`recordHistory`; typing within `TYPING_MS` merges into one step, a paste never does); `selectionchange` keeps the current step's caret up to date; Mod+Z, Mod+Shift+Z / Mod+Y and `beforeinput` historyUndo/historyRedo call `restoreHistory`. Auto-conversions (`` `x` ``, `[]`, `- `) record the typed text first, so undo brings the characters back; their internal execCommand edits are ignored by the `converting` guard. **Any new DOM-changing edit must end in `onContentChanged()`.**

## Format bar, Format menu, format tray

Every formatting command is in `FORMAT_COMMANDS` (bold / italic / underline, highlight, code, check / bullet / number → `toggleList`, codeBlock → `toggleCodeBlock`, table → `toggleTable`) with its on-state in `formatState`; `renderFormatState(bar)` sets `aria-pressed`. `toggleList` / `toggleCodeBlock` act on `touchedLines()` (the lines the selection touches, a triple click's next line left out, or the caret's line); all of one type already → back to plain lines; inside a code block, `toggleCodeBlock` turns it back into lines. The same commands reach the user three ways, all mouse-only (a "+" beside empty lines was tried and dropped: the author didn't want it):

- `#formatBar` (bold / italic / underline, highlight, code `</>`, checklist, list, numbered list, code block, table, three "A" sizes) floats above a non-empty selection; hidden while the mouse drags a selection, repositioned on `selectionchange`/scroll/resize; buttons use `mousedown` preventDefault so the selection survives. It wraps in a narrow memory (button widths, `.fmt-btn` 21 px and `.fmt-size` 19 px, are set so it and the tray fit one row at `DEFAULT_W`). Titles show the shortcut (`data-key`) or the typed syntax (`data-hint`, `typeHint`).
- "format menu": "Format" submenu at the top of the note's titlebar menu (`formatMenuItems`; `show_title_menu` takes nested `items`, `title_menu_entry` in main.rs, ids by path in chrome.js). The selection is saved when the menu opens (`saveMenuSelection`) and restored before the command runs.
- "format tray": the footer's "Aa" (`#trayBtn`, or "Formatting toolbar" in the Format submenu) shows `#formatTray`, a clone of the bar's buttons, above the footer. With just the caret, its buttons add an empty element instead (`insertEmpty`: a new list item or code block on the next line, or on the caret's line if it is an empty plain line; an empty inline code holding a U+200B; bold/italic/underline/highlight/size as typing style); with a selection they format it. It behaves like a menu: picking one of its buttons, any mousedown outside it and "Aa", Esc or the window losing focus folds it away (the author asked for that; it is not remembered).

Right-click inside the editor keeps the native menu (spellcheck, cut/copy/paste).

## Embedded editor

`index.html?defaults` runs the same page in embedded mode (`EMBED` in app.js, `html.embedded` in styles.css: no titlebar, statusbar, group stripe or window shortcuts; Tauri API taken from `window.parent` inside an iframe). The manager's settings use it in `<iframe id="defaultTextFrame">` to edit the new-note default text: it loads `get_new_note_defaults` → `(title, text, html)` and saves with `set_default_content(text, html)`; the title is saved separately (`set_default_title`). `Store::create` copies `default_title`/`default_text`/`default_html` into new notes.

Changing the editor's HTML whitelist? Also check `welcome.rs` (its HTML must survive `sanitize` and its `TEXT` must equal `toPlain` of that HTML) and the Help demos (`memo-manager`).
